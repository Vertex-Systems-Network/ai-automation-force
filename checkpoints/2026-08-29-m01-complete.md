### Decimal persistence defect found and closed

WP7 CI exposed a fixed-scale PostgreSQL `NUMERIC` representation difference such as:
- `0.42` -> `0.42000000`
- `0` -> `0E-8`

This was not value loss, but JSON textual comparison incorrectly treated semantically equal Decimal values as different canonical aggregates.

Resolution:
- canonical repository comparison now uses typed Python values instead of JSON string formatting;
- round-trip tests compare typed values;
- explicit cost/credit equality assertions protect the regression;
- no database precision, integrity constraint or fail-closed rule was weakened.
