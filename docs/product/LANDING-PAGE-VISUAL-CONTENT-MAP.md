# Landing Page Visual Content Map

## Purpose

Define the image/screenshot/demo inventory for the public marketing site so each major product capability is explained visually, truthfully and consistently.

The landing page should feel like a real production platform, not a generic AI SaaS page full of decorative gradients and stock illustrations.

Visual priority order:
1. real product screenshot using safe demo data once implemented;
2. clearly labelled conceptual product mockup before implementation;
3. generated fictional production asset where the feature itself is about generated media;
4. simple explanatory diagram when UI is not the right representation.

Do not use fake customer logos, fake case-study metrics or visuals that imply an unimplemented feature is live.

---

## Global visual direction

Final brand design remains a separate design-system decision, but marketing visuals should follow these structural rules:
- clean premium product presentation;
- strong UI/product imagery;
- generous spacing;
- restrained decoration;
- motion used to explain a workflow, not merely decorate;
- product visual remains readable on desktop and mobile;
- feature screenshots use the same synthetic demo project for continuity;
- use consistent characters/world/assets across the page so the landing itself demonstrates the platform's continuity promise.

Recommended demo concept:
- one original recurring fictional character;
- one visually distinct world;
- one 2-minute song/story project;
- 12–20 planned shots;
- character reference pack;
- keyframes;
- audio waveform/stems;
- provider fallback event;
- continuity QA rejection/approval;
- final short video thumbnail.

This single demo project can produce most marketing visuals.

- storyboard strip;
- timeline strip;

Recommended format:

Supporting mini-panel:
- front view;

## Visual 05 — Image Generation & Reuse

Three-stage composition:
1. generated candidate images;
2. approved canonical image/reference;
3. same image/reference used as first frame for a video shot.

Optional secondary example:
- scene/location reference image -> multiple shots.

Must visually show that approved images become reusable assets rather than disposable generations.

## Visual 07 — Timeline

## Visual 08 — Multi-provider routing

Show a provider routing panel/diagram:

`Canonical Shot Request`
-> provider A candidate
-> quota unavailable/failure
-> provider B fallback
-> QA
-> approved Take

Display 4–6 provider connection cards only if those providers are actually supported/evaluated at launch.

Status examples:
- Connected
- Available
- Quota low
- Waiting reset
- Evaluation
- Fallback selected

Do not expose API keys/tokens.

## Visual 09 — Continuity QA

- matching look;
- correct prop/location;

Overlay checklist/status panel instead of unverifiable numeric claims when actual scoring system is not yet implemented.

## Screenshot capture states

For every real product screenshot define:
- route/screen;
- viewport;
- demo project state;
- selected panel;
- data fixture/version;
- feature launch state;
- screenshot date/build version.

This allows screenshots to be regenerated when UI changes.

---

## Generated marketing images

AI-generated images used on the landing page should themselves use the platform's normal asset rules:
- fictional/original subjects;
- stable Asset ID;
- provider/model/provenance;
- commercial-use review;
- QA;
- no accidental logos/text;
- canonical selection;
- optimized web derivative.

Where possible, use the same canonical demo CharacterVersion and World used in product screenshots.

---

## Visual optimization targets

Each image asset should have:
- master source;
- optimized desktop derivative;
- optimized mobile derivative where needed;
- WebP/AVIF variants where practical;
- fixed dimensions/aspect ratio;
- alt text;
- light/dark-compatible background treatment if relevant;
- lazy-load policy;
- preload only for critical hero visual.

Short demo videos should have:
- poster frame;
- muted default unless audio is essential;
- captions if speech conveys information;
- no forced autoplay audio;
- reduced-motion fallback.

---

## Landing visual acceptance criteria

The marketing visual set is ready when:
- every major landing feature has one purposeful visual;
- the same demo project/character visually connects multiple sections;
- screenshots use safe synthetic data;
- implemented vs conceptual states cannot be confused;
- visuals explain actual product behavior rather than generic AI imagery;
- mobile crops/optimization/accessibility are planned;
- generated marketing assets carry provenance and rights state.
